# Stock Direction ML Platform

Production-oriented, scalable Python project for leakage-controlled market-direction research and inference. The code is organized around immutable raw data, feature engineering, timestamped financial-news ingestion, FinBERT text scoring, calendar/regime context, triple-barrier labeling, purged walk-forward validation, LightGBM + baseline, resumable Optuna tuning, calibration, evaluation, SHAP diagnostics, transaction-cost-aware backtesting, drift monitoring, and a FastAPI inference endpoint.

## Quick start (Windows)

1. Install Python 3.11+ and make sure `python` is on PATH.
2. Double-click `start_run.bat`, or run:

```powershell
python start_run.py
```

The launcher creates `.venv` when needed, verifies dependency versions, installs or repairs missing/incompatible dependencies, installs the project editable, and runs the full pipeline. The venv does not need to be manually activated because the launcher executes the pipeline with the venv's interpreter.

## Quick start (macOS/Linux/Git Bash/WSL)

```bash
./start_run.sh
```

or:

```bash
python3 start_run.py
```

## Model-training resume behavior

- Fetching: each symbol has its own parquet file and is refreshed only when stale.
- Feature engineering: each symbol has its own feature parquet and can resume symbol-by-symbol.
- Labeling: each symbol has its own processed dataset.
- Optuna: the study is stored in `checkpoints/optuna.db`; completed trials survive process restarts. Heartbeat/stale-trial settings are enabled.
- Final LightGBM: `checkpoints/lightgbm_final_checkpoint.txt` and its JSON manifest are written atomically at the configured checkpoint interval. The manifest contains a dataset fingerprint, parameter fingerprint and feature count, so incompatible checkpoints are never resumed. `init_model` continues compatible training after a crash; the completed model is stored in `artifacts/models/lightgbm_final.txt`.
- Step state: `artifacts/state/*.json` records completed pipeline stages so a later `start_run.py` skips completed stages while still allowing per-file refresh logic.

## Configuration

Edit `config/config.yaml` and `.env`.

Important settings include:

- `history_years`: default 16 (within the requested 14-18 year range)
- `symbols`: one or many instruments
- `market_data_provider`: defaults to runnable Yahoo Finance adapter; replace with a licensed point-in-time provider for production
- `enable_news` / `news_provider`: Alpha Vantage historical news (API key required) plus recent GDELT DOC enrichment
- `enable_sentiment`: local FinBERT scoring of headline/summary text; model is downloaded/cached on first use
- `optuna_pruner`: defaults to `none` for stable walk-forward comparisons; `median` is available as an opt-in
- triple-barrier horizon and barrier multipliers
- purge/embargo days
- Optuna trial count
- LightGBM training and checkpoint frequency
- transaction-cost assumptions
- drift thresholds

## Production data warning

The default Yahoo Finance adapter is a runnable fallback. A true production deployment for Indian equities should replace it with a properly licensed point-in-time market/news/corporate-actions provider and a historical constituent service. The provider interface is isolated in `src/stockml/data/providers.py` so that replacement does not require changing the feature/model code.

## Research methodology covered

The platform implements the supplied design's main methodological requirements: leakage-safe point-in-time features, fractional differentiation, triple-barrier labeling, purged/embargoed walk-forward validation, LightGBM as the primary tabular model, a linear baseline, calibrated multiclass probabilities, Optuna tuning, SHAP diagnostics, statistical evaluation, and cost-aware backtesting.

## Optional financial-news sentiment stack

`src/stockml/data/sentiment.py` provides a news-provider interface, while `src/stockml/data/finbert_sentiment.py` provides an optional FinBERT inference component. A real historical news feed must be wired in before enabling sentiment; the platform never fabricates sentiment. Install `requirements-optional.txt` and set `ENABLE_SENTIMENT=true` only when a point-in-time news feed and timestamped article text are wired into the feature pipeline. The default market-data run does not fabricate historical sentiment values.
